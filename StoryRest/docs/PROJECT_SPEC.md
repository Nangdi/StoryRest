# StoryRest 전시 시스템 사양

> 이 문서는 현장 설치 조건과 콘텐츠 규칙을 정의한다.
> 개발 작업 전에 반드시 읽고, 결정이 바뀌면 코드보다 이 문서를 먼저 갱신한다.
> 최초 작성: 2026-08-05

---

## 1. 개요

과학 주제의 상설 전시물. 관람객이 **책자에 인쇄된 ArUco 마커**를 카메라 아래에 놓으면,
시스템이 마커의 **ID · 위치 · 각도**를 계산해 해당 마커에 매핑된 **영상 또는 이미지**를
마커 기준 위치에 프로젝터로 투사한다.

동시에 별도의 프로젝터 2대가 벽면에 **과학 키워드가 떠다니는 화면**을 상시 재생한다.

---

## 2. 설치 구성

같은 빌드를 **1~3층 3개 층**에 설치한다. 장비 구성은 두 종류다.

| 층 | 프로젝터 | 카메라 | 키워드 월 | ArUco 인터랙션 |
|---|---|---|---|---|
| 1층 | 3대 | 1대 | 프로젝터 2대 | 프로젝터 1대 + 카메라 1대 |
| 2층 | 4대 | 2대 | 프로젝터 2대 | 프로젝터 2대 + 카메라 2대 |
| 3층 | 4대 | 2대 | 프로젝터 2대 | 프로젝터 2대 + 카메라 2대 |

- **키워드 월용 프로젝터 2대는 모든 층에서 고정**이다.
- 남는 프로젝터와 카메라가 **ArUco 인터랙션 세트**를 이룬다.
  - 1층 = 1세트 (프로젝터 1 : 카메라 1)
  - 2·3층 = 2세트 (프로젝터 2 : 카메라 2)
- 각 세트의 카메라와 프로젝터는 **최대한 같은 각도(동축에 가깝게)** 로 물리 설치한다.
  카메라가 본 마커 좌표를 그대로 투사 좌표로 쓸 수 있게 하기 위함이며,
  잔여 오차는 런타임 편집모드(캘리브레이션)로 보정한다.

### 세트는 서로 독립이다

**카메라 A의 검출 결과는 프로젝터 A에만 투사한다.** 세트 간에 마커를 공유하지 않는다.

- 세트마다 독립된 카메라 디바이스 · 검출기 · 캔버스 · 출력 디스플레이 · 보정값을 갖는다.
- 같은 마커 ID가 두 세트에 동시에 놓이면 **각 세트에서 각자 재생**한다(서로 간섭 없음).
- 따라서 검출·표시 파이프라인은 **세트 단위로 인스턴스화**되는 구조여야 한다.
  전역 싱글턴에 카메라·마커 상태를 두면 2세트 구성에서 깨진다.
- 보정값(위치·크기·회전)도 **세트별로 저장**한다. 마커 ID 하나에 세트 수만큼 보정값이 존재한다.

### PC 구성 — **층당 PC 1대**

한 대의 PC가 그 층의 프로젝터 3~4대와 카메라 1~2대를 **모두** 담당한다.
따라서 하나의 Unity 프로세스가 다음을 동시에 처리해야 한다.

- 멀티 디스플레이 출력 3~4개 (`Display.displays[n].Activate()`)
- 카메라 캡처 + ArUco 검출 1~2채널
- 영상 디코딩 (동시 인식 마커 수만큼)
- 키워드 월 애니메이션 상시 재생

**설계상 지켜야 할 것**

- 카메라 캡처와 마커 검출은 **메인 스레드 밖 또는 프레임 분산**으로 처리한다.
  검출을 매 프레임 전부 돌리면 4화면 렌더와 경합한다.
- 검출 해상도는 표시 해상도와 분리한다. 검출은 낮은 해상도로 충분하다.
- 영상은 **필요할 때만 디코딩**한다. 안 보이는 마커의 `VideoPlayer`는 정지시킨다.
- GPU 디코딩 가능한 코덱(H.264)을 쓰고, 동시 재생 상한을 설정으로 둔다.
- 층별 부하가 다르므로(1층 3화면·1카메라 / 2·3층 4화면·2카메라)
  **2·3층 구성을 기준으로 사양을 잡는다.**

## 3. 화면 역할

### 3.1 키워드 월 (프로젝터 2대)
- 벽면에 과학 키워드가 떠다니는 앰비언트 화면.
- 관람객 인터랙션 없음. 상시 루프.
- 낱말마다 다른 움직임(직선·물결·궤도·제자리·지그재그)·크기·색·투명도를 갖는다.
- 낱말 목록은 `floor_<N>/keywords.txt`, 동작 설정은 `keywordwall.json`.
  구현 세부는 `ARCHITECTURE.md` §10.

### 3.2 ArUco 인터랙션 (프로젝터 1~2대 + 카메라 1~2대)
- 카메라가 마커를 검출 → ID / 4꼭짓점 / 각도 산출.
- 마커 ID에 매핑된 콘텐츠를 **마커 평면 기준 위치·각도**에 맞춰 투사.
- 마커가 사라지면 콘텐츠도 사라진다(홀드 시간 후).
- 마커를 회전·이동시키면 콘텐츠도 따라간다.

## 4. 마커 ↔ 콘텐츠 매핑

- 마커 **개수는 고정이 아니다.** 콘텐츠 파일이 추가되면 그 마커가 자동으로 활성화되는 구조여야 한다.
- 매핑 단위는 **마커 번호(ID) ↔ 과학 콘텐츠 1건**.
- 콘텐츠 종류: **영상(video) 또는 이미지(image)**.

### 콘텐츠 경로 — **마커 ID 폴더 구조**

```
Assets/StreamingAssets/
└─ floor_<N>/          (N = 1, 2, 3 — 이 빌드가 설치될 층)
   ├─ 0/               ← 폴더 이름 = 마커 ID
   │  └─ *.mp4         ← 이 마커에 매핑된 영상
   ├─ 1/
   │  └─ *.mp4
   └─ 12/
      └─ *.mp4
```

- **폴더 이름이 곧 마커 ID다.** 파일명은 자유이며, 폴더 안의 영상을 찾아 재생한다.
- **폴더당 영상은 1개**다. 여러 개가 들어 있으면 첫 번째를 쓰고 경고를 남긴다.
- **영상에 오디오는 없다.** 오디오 트랙을 재생하지 않으므로 동시 재생 시 소리가 겹칠 일이 없다.
- 폴더를 추가하는 것만으로 그 마커가 활성화된다. 코드·설정 수정 불필요.
- 숫자로 파싱되지 않는 폴더 이름은 무시한다.
- 빌드 후 실제 경로: `<앱이름>_Data/StreamingAssets/floor_<N>/`

### 층 지정 — `Setting.json`의 `floor` 값

**빌드는 3개 층 공통으로 하나만 유지한다.** 어느 층인지는 실행 시 설정으로 읽는다.

```
StreamingAssets/Setting.json
{
  "floor": 1        // 1~3. 이 값으로 floor_<N>/ 폴더를 고른다
}
```

- 현장 설치 시 이 파일의 숫자만 바꾸면 층이 바뀐다.
- 해당 `floor_<N>/` 폴더가 없으면 명확한 에러를 남기고 빈 상태로 뜬다. 조용히 넘어가지 않는다.

세트 정의와 마커 보정값은 `aruco.json`에 둔다(→ §6).
이 프로젝트는 이미 `port.json` / `tcp.json` / `Setting.json`으로 관심사별 파일을 나누고 있으므로
ArUco 관련 설정은 `aruco.json` 한 파일로 모은다.

## 5. 영상 재생 — **AVPro Video**

Unity 기본 `VideoPlayer` 대신 **AVPro Video**를 사용한다. (`Assets/AVProVideo/`, 임포트 완료)

- Windows 백엔드에서 하드웨어 디코딩이 안정적이고, **다중 인스턴스 동시 재생**에 강하다.
  층당 PC 1대로 여러 마커 영상을 동시에 디코딩해야 하는 본 구성에 맞다.
- 재생 소스는 `StreamingAssets` 상대 경로로 지정한다(빌드 후에도 같은 경로 규칙 유지).
- 오디오는 사용하지 않으므로 **오디오 출력을 끈 상태**로 둔다.
- 표시 경로: AVPro가 만든 텍스처를 `ArUcoWarpedImage`(마커 평면 워프 UI)에 물린다.
  → `ArUcoPages.asmdef`에 **AVPro Video 런타임 어셈블리 참조 추가**가 필요하다.
- 안 보이는 마커의 플레이어는 정지시켜 디코딩 부하를 줄인다(→ §2 부하 항목).

## 6. 런타임 배치 편집과 저장 (필수)

카메라와 프로젝터를 물리적으로 완전히 같은 각도에 두는 것은 불가능하므로,
**어느 위치에 얼마나 크게 띄울지는 현장에서 눈으로 보며 맞춘다.**
Unity 에디터 없이, 실행 중인 전시 화면에서 조정하고 그 값이 파일로 남아야 한다.

### 요구 사항

- 실행 중 **편집모드**로 진입해 마커를 선택하고 위치·크기·회전을 조정한다.
- 조정한 값은 **즉시 파일에 저장**된다(짧은 지연 후 자동 저장 + 즉시 저장 키).
  전시장 PC는 예고 없이 꺼지므로 "종료 시 저장"에 의존하지 않는다.
- 재시작하면 저장된 값이 그대로 복원된다.
- 조정값은 **마커 한 변 길이를 1로 보는 상대 좌표**로 저장한다.
  카메라 높이나 줌이 바뀌어도 배치가 유지되고, 마커를 돌리면 콘텐츠도 같은 자리에 머문다.
- 설정에 없는 마커가 처음 잡히면 **기본값 항목을 자동 생성**한다.
  새 콘텐츠를 넣고 바로 편집모드에서 맞출 수 있어야 한다(json 선편집 불필요).
- **관람객이 건드릴 수 없어야 한다.** 편집모드는 명시적 키로만 진입하고,
  평상시 화면에는 어떤 편집 UI도 보이지 않는다.

### 세트별로 따로 저장한다

같은 마커 ID라도 **세트가 다르면 별개의 보정값**을 갖는다(→ §2).
카메라 A와 카메라 B의 설치 각도가 다르므로 값을 공유하면 안 된다.

```
StreamingAssets/aruco.json
{
  "sets": [
    {
      "name": "A",
      "camera": { "deviceId": 0, "backend": 0, ... },
      "displayIndex": 1,                  // 이 세트가 투사할 프로젝터
      "markers": [
        { "id": 3, "scale": 1.2, "offsetX": 0.1, "offsetY": -0.4, "rotationOffset": 0 }
      ]
    },
    { "name": "B", "camera": { "deviceId": 1 }, "displayIndex": 2, "markers": [ ... ] }
  ]
}
```

- **세트 수는 이 배열이 결정한다.** 층수로 세트 수를 추론하지 않는다
  (1층은 세트 1개, 2·3층은 2개지만, 설치가 바뀌어도 코드를 고치지 않기 위함).
- 층이 다르면 콘텐츠 폴더가 다르므로, 층별로 별도의 `aruco.json`을 쓰는 셈이 된다.

### 기존 패키지 활용

`ArUcoAdjustMode`가 이미 편집모드(F1, 방향키/`+`/`-`/`[`/`]`, 1.5초 후 자동 저장)를 제공하고,
`ArUcoMarkerConfig`가 상대 좌표 필드(`scale` / `offsetX` / `offsetY` / `rotationOffset`)를 갖고 있다.
`ArUcoConfigStore`에는 호스트 프로젝트가 입출력을 가로챌 수 있는 `Loader` / `Saver` 훅도 있다.

**고쳐야 할 것은 저장 구조뿐이다** — 현재 `markers`가 최상위에 하나뿐이라 세트 개념이 없다.
이를 `sets[].markers`로 바꾸고, 편집모드가 **현재 선택된 세트**를 대상으로 동작하도록 확장한다.

## 7. 기존 자산 현황

### `Assets/ArUcoPages/` (자체 제작 패키지)
마커 4꼭짓점 → 호모그래피로 평면에 이미지를 눕히는 패키지. 캘리브레이션 불필요.
자세한 사용법은 `Assets/ArUcoPages/README.md` 참조.

**이 프로젝트 요구사항과의 차이 — 확장이 필요한 지점:**

| 항목 | 현재 패키지 | 본 프로젝트 요구 |
|---|---|---|
| 콘텐츠 종류 | 이미지(png/jpg)만 | **영상 (AVPro Video)** |
| 콘텐츠 탐색 | 평면 파일 스캔 `Images/image_<ID>.png` | **폴더 스캔 `floor_<N>/<ID>/*`** |
| 카메라 | 1대 (`camera.deviceId` 단일) | **최대 2대 동시, 세트별 독립** |
| 출력 | 단일 ScreenSpaceOverlay 캔버스 | **디스플레이(프로젝터)별 분리 출력** |
| 보정값 | 마커 ID당 1벌 | **세트 × 마커 ID당 1벌** |
| 부하 | 단일 화면 전제 | **한 PC에서 4화면 + 2카메라 + 영상 디코딩** |
| 키워드 월 | 없음 | 프로젝터 2대분 별도 화면 필요 |

재사용할 핵심은 `ArUcoHomography`(4꼭짓점 → 평면)와 `ArUcoWarpedImage`(비사각형 워프 UI)다.
이 둘은 그대로 쓰고, 그 위의 **검출기·이미지 라이브러리·오버레이는 세트 단위로 재구성**한다.

### 기타
- `Assets/AVProVideo/` — 영상 재생. Windows 플러그인 포함. (에셋스토어 유료)
- `Assets/OpenCVForUnity/` — 마커 검출 기반. (에셋스토어 유료, 리포에 포함)
- `Assets/3.Script/` — `GameManager`, `GameTimer`, `JsonManager`, RS232/TCP 통신, `SettingsPanelUI`(ESC 설정창).
- `Assets/StreamingAssets/Setting.json` — 현재 비어 있음(`{}`). **여기에 `floor`와 세트 정의를 넣는다.**

### 미확정 (결정되면 이 절을 갱신)

1. **영상 규격** — 코덱/해상도. (H.264 / mp4 권장 — 하드웨어 디코딩)
2. **재생 정책** — 마커가 인식되는 동안 **루프 재생**, 마커가 사라지면 정지하고
   다시 인식되면 **처음부터** 재생하는 것으로 가정한다. 다르면 이 항목을 고칠 것.
3. **동시 인식 마커 수 상한** — 책자를 여러 명이 동시에 올릴 때의 처리.
   PC 1대 구성이므로 영상 동시 디코딩 상한과 직결된다.
4. **키워드 목록 내용** — 표시 방식과 구조는 정해졌다(→ ARCHITECTURE §10).
   실제 낱말은 아직 예시 상태이며, `floor_<N>/keywords.txt` 에 층별로 채우면 된다.
5. **디스플레이 번호 배정** — 층마다 프로젝터가 3~4대이고 역할이 다르다.
   `aruco.json` 의 `sets[].displayIndex` 와 `keywordwall.json` 의 `displayIndexes` 로 지정하며,
   겹치면 시작할 때 경고한다. 실제 값은 현장에서 확인해 넣는다.

## 9. 개발 원칙

- 층·장비 수 차이는 **코드 분기가 아니라 설정 데이터**로 흡수한다. 빌드는 하나로 유지한다.
- 마커/콘텐츠 추가는 **파일만 넣으면 되는** 구조를 유지한다(코드·설정 수정 불필요).
- 검출·표시는 **세트 단위 인스턴스**로 만든다. 카메라/마커 상태를 전역 싱글턴에 두지 않는다.
- 현장 미세조정(위치·크기·회전)은 런타임에서 가능해야 하고, 그 값은 **세트별로** 파일에 영속화한다.
  에디터를 열어야만 고칠 수 있는 값은 만들지 않는다.
- 전시장 PC는 예고 없이 꺼진다. 상태는 **바뀐 시점에 저장**하고, 종료 처리에 의존하지 않는다.
