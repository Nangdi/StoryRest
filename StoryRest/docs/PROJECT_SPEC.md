# StoryRest 전시 시스템 사양

> 이 문서는 현장 설치 조건과 콘텐츠 규칙을 정의한다.
> 개발 작업 전에 반드시 읽고, 결정이 바뀌면 코드보다 이 문서를 먼저 갱신한다.
> 최초 작성: 2026-08-05

---

## 1. 개요

과학 주제의 상설 전시물. 관람객이 **책자에 인쇄된 ArUco 마커**를 카메라 아래에 놓으면,
시스템이 마커의 **ID · 위치 · 각도**를 계산해 해당 마커에 매핑된 **영상 또는 이미지**를
마커 기준 위치에 프로젝터로 투사한다.

동시에 별도의 프로젝터 2대가 벽면에 **과학 키워드가 떠다니는 화면**을 상시 재생한다.

---

## 2. 설치 구성

같은 빌드를 **1~3층 3개 층**에 설치한다. 장비 구성은 두 종류다.

| 층 | 프로젝터 | 카메라 | 키워드 월 | ArUco 인터랙션 |
|---|---|---|---|---|
| 1층 | 3대 | 1대 | 프로젝터 2대 | 프로젝터 1대 + 카메라 1대 |
| 2층 | 4대 | 2대 | 프로젝터 2대 | 프로젝터 2대 + 카메라 2대 |
| 3층 | 4대 | 2대 | 프로젝터 2대 | 프로젝터 2대 + 카메라 2대 |

- **키워드 월용 프로젝터 2대는 모든 층에서 고정**이다.
- 남는 프로젝터와 카메라가 **ArUco 인터랙션 세트**를 이룬다.
  - 1층 = 1세트 (프로젝터 1 : 카메라 1)
  - 2·3층 = 2세트 (프로젝터 2 : 카메라 2)
- 각 세트의 카메라와 프로젝터는 **최대한 같은 각도(동축에 가깝게)** 로 물리 설치한다.
  카메라가 본 마커 좌표를 그대로 투사 좌표로 쓸 수 있게 하기 위함이며,
  잔여 오차는 런타임 편집모드(캘리브레이션)로 보정한다.

### 세트는 서로 독립이다

**카메라 A의 검출 결과는 프로젝터 A에만 투사한다.** 세트 간에 마커를 공유하지 않는다.

- 세트마다 독립된 카메라 디바이스 · 검출기 · 캔버스 · 출력 디스플레이 · 보정값을 갖는다.
- 같은 마커 ID가 두 세트에 동시에 놓이면 **각 세트에서 각자 재생**한다(서로 간섭 없음).
- 따라서 검출·표시 파이프라인은 **세트 단위로 인스턴스화**되는 구조여야 한다.
  전역 싱글턴에 카메라·마커 상태를 두면 2세트 구성에서 깨진다.
- 보정값(위치·크기·회전)도 **세트별로 저장**한다. 마커 ID 하나에 세트 수만큼 보정값이 존재한다.

### PC 구성 — **역할(role)로 나눈다**

PC 그래픽카드의 출력 포트가 **3개**라 프로젝터 4대를 한 PC 에 붙일 수 없다(2026-09-11 확인).
그래서 2·3층은 PC 를 둘로 나누되, 나누는 기준은 포트 수가 아니라 **하는 일**이다.

| role | 맡는 일 | 프로젝터 | 카메라 | 통신 |
|---|---|---|---|---|
| `all` | 카메라·마커·영상 + 키워드 월 전부 | 3 | 1 | 없음 |
| `aruco` | 카메라·마커·영상만 | 2 | 2 | **서버** — 관람 기록을 월 PC 로 보냄 |
| `wall` | 키워드 월만 | 2 | 0 | **클라이언트** — ArUco PC 에서 관람 기록을 받음 |

| 층 | PC | role |
|---|---|---|
| 1층 | 1대 | `all` |
| 2·3층 | 2대 | `aruco` + `wall` |

- 역할은 `Setting.json` 의 `role` 값이다(→ §4). **빌드는 하나**고, 층과 마찬가지로 파일 한 줄로 역할이 바뀐다.
- 월 PC 는 통신이 끊겨도 월을 계속 띄운다. ArUco PC 는 월 PC 가 없어도 마커 인식·투사·기록을 계속한다.
  두 PC 는 서로 없어도 각자 돌고, 연결은 관람 기록을 나르는 데만 쓴다(→ §5 관람 기록).
- `aruco` PC 는 프로젝터 2대만 쓰므로 남는 포트에 **관리용 모니터**를 붙일 수 있다.
  편집모드·설정창을 프로젝터 빛 아래에서 조작하지 않아도 된다.
- 카메라 수는 역할이 아니라 `aruco.json` 의 `sets[]` 가 정한다. `all` 이 1카메라인 것은 1층 설치가 그래서지 코드가 제한하는 것이 아니다.
- 디스플레이 번호는 역할마다 다르다 — 월 PC 는 세트가 없어 월이 0번부터 시작한다.
  `keywordwall.json` 의 `walls[].roles` 로 역할별 항목을 둔다(→ ARCHITECTURE §4).

`all` 로 뜨는 PC 는 하나의 Unity 프로세스가 다음을 동시에 처리한다.
`aruco` / `wall` 은 이 중 자기 몫만 한다.

- 멀티 디스플레이 출력 2~3개 (`Display.displays[n].Activate()`)
- 카메라 캡처 + ArUco 검출 1~2채널
- 영상 디코딩 (동시 인식 마커 수만큼)
- 키워드 월 애니메이션 상시 재생

**설계상 지켜야 할 것**

- 카메라 캡처와 마커 검출은 **메인 스레드 밖 또는 프레임 분산**으로 처리한다.
  검출을 매 프레임 전부 돌리면 4화면 렌더와 경합한다.
- 검출 해상도는 표시 해상도와 분리한다. 검출은 낮은 해상도로 충분하다.
- 영상은 **필요할 때만 디코딩**한다. 안 보이는 마커의 `VideoPlayer`는 정지시킨다.
- GPU 디코딩 가능한 코덱(H.264)을 쓰고, 동시 재생 상한을 설정으로 둔다.
- 가장 무거운 PC 는 2·3층의 `aruco` PC(2화면·2카메라·영상 디코딩)다. **이걸 기준으로 사양을 잡는다.**
  `wall` PC 는 글자 애니메이션뿐이라 낮은 사양이어도 된다.

## 3. 화면 역할

### 3.1 키워드 월 (프로젝터 2대)
- 벽면에 과학 키워드가 떠다니는 앰비언트 화면.
- 관람객 인터랙션 없음. 상시 루프.
- 낱말마다 다른 움직임(직선·물결·궤도·제자리·지그재그)·크기·색·투명도를 갖는다.
- 낱말 목록은 `floor_<N>/keywords.txt`, 동작 설정은 `keywordwall.json`.
  구현 세부는 `ARCHITECTURE.md` §10.

### 3.2 ArUco 인터랙션 (프로젝터 1~2대 + 카메라 1~2대)
- 카메라가 마커를 검출 → ID / 4꼭짓점 / 각도 산출.
- 마커 ID에 매핑된 콘텐츠를 **마커 평면 기준 위치·각도**에 맞춰 투사.
- 마커가 사라지면 콘텐츠도 사라진다(홀드 시간 후). 영상은 잠시 멈춰 두었다가 곧 돌아오면 이어서 튼다(→ §5 재생 정책).
- 마커를 회전·이동시키면 콘텐츠도 따라간다.
- 마커가 얼마나 관람됐는지 건별로 기록한다(→ §5 관람 기록). 순위 화면은 미정(→ §8).

## 4. 마커 ↔ 콘텐츠 매핑

- 마커 **개수는 고정이 아니다.** 콘텐츠 파일이 추가되면 그 마커가 자동으로 활성화되는 구조여야 한다.
- 매핑 단위는 **마커 번호(ID) ↔ 과학 콘텐츠 1건**.
- 콘텐츠 종류: **영상(video) 과 이미지(image)**. 한 마커가 **둘을 동시에** 띄울 수 있다.

### 콘텐츠 경로 — **마커 ID 폴더 구조**

```
Assets/StreamingAssets/
└─ floor_<N>/               (N = 1, 2, 3 — 이 빌드가 설치될 층)
   ├─ 16/                    ← 폴더 이름 = 마커 ID
   │  └─ 광합성.mp4          ← 영상 하나
   ├─ 17_별의일생/           ← 앞자리 숫자만 ID 로 읽는다 (= 17번)
   │  ├─ 01_별의일생.mp4
   │  └─ 02_설명.png         ← 영상과 이미지를 함께 띄운다
   └─ 18/                    ← 비워 두면 그 마커는 안내 문구만 뜬다
```

- **폴더 이름 앞자리 숫자가 곧 마커 ID 다.** 뒤에 무엇을 적든 무시하므로
  `17_별의일생` 처럼 제목을 붙여 둔다. 폴더가 70개 넘어가도 탐색기에서 바로 구분된다.
  숫자로 시작하지 않는 폴더(`_보관` 등)는 그냥 지나간다.
- **폴더 안의 파일을 전부 띄운다.** 영상과 이미지가 섞여 있어도 둘 다 뜬다.
  종류는 확장자로 판단한다 — 사람이 어디에 넣을지 고를 필요가 없다.
  - 영상: `.mp4` `.mov` `.m4v` `.wmv` `.avi` `.mkv` `.webm`
  - 이미지: `.png` `.jpg` `.jpeg` (투명 png 권장 — 검은 배경이 그대로 빛이 된다)
- **그리는 순서는 파일 이름순**이고, 나중 것이 위에 올라간다.
  순서가 중요하면 `01_`, `02_` 같은 접두사를 붙인다.
- **개수가 늘어나도 설정 파일을 먼저 고칠 필요가 없다.** 파일을 넣으면 그 마커가
  활성화되고, 배치는 현장에서 편집모드로 맞춘다(→ §6).
  한 폴더에 여러 장이 있으면 첫 장은 마커 자리에, 다음부터는 오른쪽으로 나란히 놓이며
  이후 장마다 따로 옮길 수 있다.
- **영상에 오디오는 없다.** 오디오 트랙을 재생하지 않으므로 동시 재생 시 소리가 겹칠 일이 없다.
- 이미지는 표시할 때 읽어 메모리에 두고, 사용되지 않으면 오래된 것부터 놓아준다
  (`maxCachedImages`). **사진 원본을 그대로 넣지 말고** 투사 크기에 맞춰 줄여 넣는다
  (4096px 를 넘으면 시작할 때 경고한다).
- 빌드 후 실제 경로: `<앱이름>_Data/StreamingAssets/floor_<N>/`

### 층 · 역할 지정 — `Setting.json`의 `floor` · `role` 값

**빌드는 3개 층 · 3개 역할 공통으로 하나만 유지한다.** 어느 층 · 어느 역할인지는 실행 시 설정으로 읽는다.

```
<persistentDataPath>/Setting.json
{
  "floor": 1,               // 1~3. 이 값으로 floor_<N>/ 폴더를 고른다
  "role": "all",            // all / aruco / wall (→ §2)
  "statsHost": "127.0.0.1", // wall 일 때 붙을 ArUco PC 의 주소
  "statsPort": 5100         // aruco 가 열고 wall 이 붙는 포트
}
```

- 현장 설치 시 이 파일의 값만 바꾸면 층과 역할이 바뀐다.
- `all` 은 `statsHost` / `statsPort` 를 쓰지 않는다. 2·3층 월 PC 의 `statsHost` 에는 같은 층 ArUco PC 의 고정 IP 를 넣는다.
- `aruco.json` 과 같은 이유로 `persistentDataPath` 에 둔다(→ §6 "빌드를 다시 넣어도 남아야 한다").
  `StreamingAssets/Setting.json` 은 첫 실행 때 복사되는 기본값이다.
- 해당 `floor_<N>/` 폴더가 없으면 명확한 에러를 남기고 빈 상태로 뜬다. 조용히 넘어가지 않는다.

세트 정의와 마커 보정값은 `aruco.json`에 둔다(→ §6).
이 프로젝트는 이미 `port.json` / `tcp.json` / `Setting.json`으로 관심사별 파일을 나누고 있으므로
ArUco 관련 설정은 `aruco.json` 한 파일로 모은다.

## 5. 영상 재생 — **AVPro Video**

Unity 기본 `VideoPlayer` 대신 **AVPro Video**를 사용한다. (`Assets/AVProVideo/`, 임포트 완료)

- Windows 백엔드에서 하드웨어 디코딩이 안정적이고, **다중 인스턴스 동시 재생**에 강하다.
  층당 PC 1대로 여러 마커 영상을 동시에 디코딩해야 하는 본 구성에 맞다.
- 재생 소스는 `StreamingAssets` 상대 경로로 지정한다(빌드 후에도 같은 경로 규칙 유지).
- 오디오는 사용하지 않으므로 **오디오 출력을 끈 상태**로 둔다.
- 표시 경로: AVPro가 만든 텍스처를 `ArUcoWarpedImage`(마커 평면 워프 UI)에 물린다.
  → `ArUcoPages.asmdef`에 **AVPro Video 런타임 어셈블리 참조 추가**가 필요하다.
- 안 보이는 마커의 플레이어는 정지시켜 디코딩 부하를 줄인다(→ §2 부하 항목).

### 재생 정책 — 놓쳐도 끊지 않는다

마커 인식은 손이 가리거나 조명이 튀면 **수시로 잠깐씩 끊긴다.** 그때마다 영상을 처음부터 다시 틀면
관람자는 같은 도입부만 반복해서 보게 된다. 그래서 "놓침" 과 "끝남" 을 시간으로 가른다.

```
마커 보임 ──────────────▶ 영상 루프 재생
마커 놓침 ─ holdSeconds(0.3s) ─▶ 콘텐츠 숨김 (책자 없는 자리에 빛을 쏘면 안 된다) · 영상은 그 자리에서 멈춤
        ─ resumeGrace(20s) 안에 돌아옴 ─▶ 콘텐츠 다시 표시 · 영상은 멈춘 자리에서 이어서
        ─ resumeGrace 를 넘김 ────────▶ 관람 종료. 영상은 처음으로 되감기. 다음 인식은 새 관람
```

- 값은 `aruco.json` 의 `viewResumeGraceSeconds`(기본 20초). `holdSeconds` 보다 길어야 한다.
  책장을 넘기거나 옆 사람과 얘기하다 돌아오는 시간을 덮는 값이다. 너무 길면 **다음 관람객**이
  앞사람이 보던 중간부터 보게 되고 그 사람은 세어지지 않으므로, 한 사람이 자리를 비우는 시간보다
  조금 긴 정도가 적당하다. ESC 설정창에서 현장에 맞춰 조절한다.
- **영상이 끝나면 처음부터 다시 돈다(루프).** 마커가 놓여 있는 한 몇 번을 돌든 화면은 비지 않는다.
  루프는 관람 수와 무관하다 — 관람은 "마커가 놓여 있던 한 구간" 이지 "영상이 재생된 횟수" 가 아니다.
- 멈췄다 이어가는 이유: 놓친 사이에 영상이 계속 흘러가면 돌아왔을 때 장면을 건너뛴 것처럼 보인다.

### 관람 기록

**관람 1회 = 영상이 끊기지 않고 이어진 한 구간.** 위 재생 정책과 같은 시간을 쓰므로
"한 번 세어진 관람" 과 "한 번 이어서 재생된 영상" 이 항상 같은 것을 가리킨다.

- 마커가 처음 잡힌 뒤 `viewMinDwellSeconds`(기본 1초) 동안 유지돼야 관람으로 센다.
  그 전에 사라지면 책장을 넘기다 스친 것이거나 오인식으로 보고 세지 않는다.
- 놓쳐도 `viewResumeGraceSeconds` 안에 돌아오면 같은 관람이다. 넘기면 끝난 것이다.
- 끝날 때 한 건을 적는다: **시작 시각 · 층 · 세트 · 마커 ID · 지속시간(초)**.
  지속시간은 처음 잡힌 때부터 마지막으로 보인 때까지다(놓친 구간 포함).
- 편집모드 중에는 세지 않는다. 설치자가 배치를 맞추느라 올려 둔 마커는 관람이 아니다.
- 파일: `<persistentDataPath>/stats/views_YYYY-MM-DD.csv` — 날짜별, 한 건에 한 줄, append 만 한다.
  `started_at,floor,set,marker,seconds` / `2026-09-11T14:03:27,2,A,17,42.5`
- **집계가 아니라 건별 원본을 남긴다.** 순위 화면에 무엇을 보여줄지(오늘의 추천, 오늘·일주일·한 달 순위 …)는
  아직 정해지지 않았고, 기준이 정해지거나 바뀌어도 이 파일에서 다시 셀 수 있다.
  하루 수천 건이라도 몇백 KB 라 실행 중에 읽어 집계하는 데 무리가 없다.
- 원본은 마커를 인식하는 PC(`all` / `aruco`)에 남는다. 2·3층은 월이 다른 PC 에 있으므로
  ArUco PC 가 **한 건 적을 때마다 같은 줄을 월 PC 로 보내고**, 월 PC 는 받은 것을 자기 `stats/` 에 **미러**로 적는다.
  월 PC 가 재시작하거나 선이 빠졌다 돌아오면 최근 31일치를 통째로 다시 받아 맞춘다.
  그래서 순위 화면을 만드는 쪽은 역할을 몰라도 된다 — 어느 PC 든 `stats/` 폴더를 읽으면 같은 것이 보인다.
- 층끼리는 연결이 없다. 층별 순위만 낼 수 있다.
- `recordViews: false` 로 끌 수 있다(개발 PC 에서 통계를 더럽히지 않으려 할 때).

### 이미지

이미지는 AVPro 를 거치지 않는다. 파일을 읽어 `Texture2D` 로 올린 뒤 영상과 **같은 워프 경로**로 그린다.
그리는 쪽에서 보면 영상이든 이미지든 "텍스처 한 장"이라 표시 코드가 갈라지지 않는다.

- 읽기는 화면을 멈추지 않게 비동기로 한다(디코딩이 워커 스레드에서 도는 `UnityWebRequestTexture`).
  준비될 때까지는 자리표시 색판이 뜨고, 다음 프레임부터 이미지로 바뀐다.
- 한 번 읽은 텍스처는 캐시에 남겨 두고 **세트끼리 공유**한다. 같은 파일을 두 번 올리지 않는다
  (읽기 전용이라 공유해도 세트 독립성이 깨지지 않는다).
- 캐시가 `maxCachedImages` 를 넘으면 화면에 없는 것 중 가장 오래된 것부터 버린다.

## 6. 런타임 배치 편집과 저장 (필수)

카메라와 프로젝터를 물리적으로 완전히 같은 각도에 두는 것은 불가능하므로,
**어느 위치에 얼마나 크게 띄울지는 현장에서 눈으로 보며 맞춘다.**
Unity 에디터 없이, 실행 중인 전시 화면에서 조정하고 그 값이 파일로 남아야 한다.

### 요구 사항

- 실행 중 **편집모드**로 진입해 마커를 선택하고 위치·크기·회전을 조정한다.
- 조정한 값은 **즉시 파일에 저장**된다(짧은 지연 후 자동 저장 + 즉시 저장 키).
  전시장 PC는 예고 없이 꺼지므로 "종료 시 저장"에 의존하지 않는다.
- 재시작하면 저장된 값이 그대로 복원된다.
- 조정값은 **마커 한 변 길이를 1로 보는 상대 좌표**로 저장한다.
  카메라 높이나 줌이 바뀌어도 배치가 유지되고, 마커를 돌리면 콘텐츠도 같은 자리에 머문다.
- 설정에 없는 마커가 처음 잡히면 **기본값 항목을 자동 생성**한다.
  새 콘텐츠를 넣고 바로 편집모드에서 맞출 수 있어야 한다(json 선편집 불필요).
- **관람객이 건드릴 수 없어야 한다.** 편집모드는 명시적 키로만 진입하고,
  평상시 화면에는 어떤 편집 UI도 보이지 않는다.

### 세트별로 따로 저장한다

같은 마커 ID라도 **세트가 다르면 별개의 보정값**을 갖는다(→ §2).
카메라 A와 카메라 B의 설치 각도가 다르므로 값을 공유하면 안 된다.

```
<persistentDataPath>/aruco.json      (Windows: %USERPROFILE%\AppData\LocalLow\<회사>\StoryRest\)
{
  "sets": [
    {
      "name": "A",
      "camera": { "deviceId": 0, "backend": 0, ... },
      "displayIndex": 1,                  // 이 세트가 투사할 프로젝터
      "markers": [
        { "id": 3, "scale": 1.2, "offsetX": 0.1, "offsetY": -0.4, "rotationOffset": 0,
          "items": [
            { "file": "01_별의일생.mp4", "scale": 1.0, "offsetX": 0.0,  "offsetY": 0 },
            { "file": "02_설명.png",     "scale": 0.6, "offsetX": 1.1,  "offsetY": 0 }
          ] }
      ]
    },
    { "name": "B", "camera": { "deviceId": 1 }, "displayIndex": 2, "markers": [ ... ] }
  ]
}
```

- **배치는 세 겹으로 쌓인다 — 세트 공통 → 마커 → 파일.**
  편집모드의 맨 방향키는 세트 공통을 움직이고, `Ctrl` 을 더하면 선택한 마커(또는 파일 한 장)만 움직인다.
  마커 값을 움직이면 그 마커의 콘텐츠가 통째로 움직이고, `items[]` 값은 파일 한 장만 움직인다.
  최종 위치 = `globalOffset + markers[].offset + items[].offset`, 크기는 곱으로 쌓인다.
  콘텐츠가 한 장뿐인 마커는 `items` 를 신경 쓸 일이 없다(마커 값만 만지면 된다).
- `items[].file` 은 **파일 이름**이다. 파일 이름을 바꾸면 그 장의 보정값은 초기값으로 돌아간다.
  폴더에서 사라진 파일의 항목은 남아 있어도 무시되므로, 되돌려 놓으면 값도 되살아난다.
- 처음 잡힌 파일은 자동으로 항목이 생긴다. 첫 장은 마커 자리 그대로,
  둘째 장부터는 오른쪽으로 한 칸씩(마커 한 변의 1.1배) 떨어뜨려 서로 가리지 않게 둔다.
- **세트 수는 이 배열이 결정한다.** 층수로 세트 수를 추론하지 않는다
  (1층은 세트 1개, 2·3층은 2개지만, 설치가 바뀌어도 코드를 고치지 않기 위함).
- 층이 다르면 콘텐츠 폴더가 다르므로, 층별로 별도의 `aruco.json`을 쓰는 셈이 된다.

### 빌드를 다시 넣어도 남아야 한다

현장에서 맞춘 값은 **`persistentDataPath`** 에 저장한다. `StreamingAssets` 는 빌드 폴더 안에 있어
빌드를 새로 복사해 넣으면 통째로 덮어써지고, 며칠 걸려 맞춘 배치·보정값이 함께 사라진다.

- `StreamingAssets/aruco.json` 은 **기본값 원본**이다. `persistentDataPath` 에 파일이 없을 때(첫 실행)
  한 번 복사해 오고, 그 뒤로는 복사본만 읽고 쓴다. 층 번호(`Setting.json`)도 같은 방식이다.
  `keywordwall.json` 은 현장에서 바꾸는 값이 없으므로 `StreamingAssets` 에 그대로 둔다.
- 그래서 빌드에 실린 `aruco.json` 을 고쳐도 **이미 실행한 적 있는 PC 에는 반영되지 않는다.**
  새 기본값을 적용하려면 `persistentDataPath` 의 파일을 지우거나 직접 고친다.
  실제 경로는 시작 로그의 `설정 파일:` 줄에 찍힌다.

### 기존 패키지 활용

`ArUcoAdjustMode`가 이미 편집모드(F1, 방향키/`+`/`-`/`[`/`]`, 1.5초 후 자동 저장)를 제공하고,
`ArUcoMarkerConfig`가 상대 좌표 필드(`scale` / `offsetX` / `offsetY` / `rotationOffset`)를 갖고 있다.
`ArUcoConfigStore`에는 호스트 프로젝트가 입출력을 가로챌 수 있는 `Loader` / `Saver` 훅도 있다.

**고쳐야 할 것은 저장 구조뿐이다** — 현재 `markers`가 최상위에 하나뿐이라 세트 개념이 없다.
이를 `sets[].markers`로 바꾸고, 편집모드가 **현재 선택된 세트**를 대상으로 동작하도록 확장한다.

## 7. 기존 자산 현황

### `Assets/ArUcoPages/` (자체 제작 패키지)
마커 4꼭짓점 → 호모그래피로 평면에 이미지를 눕히는 패키지. 캘리브레이션 불필요.
자세한 사용법은 `Assets/ArUcoPages/README.md` 참조.

**이 프로젝트 요구사항과의 차이 — 확장이 필요한 지점:**

| 항목 | 현재 패키지 | 본 프로젝트 요구 |
|---|---|---|
| 콘텐츠 종류 | 이미지(png/jpg)만 | **영상 (AVPro Video)** |
| 콘텐츠 탐색 | 평면 파일 스캔 `Images/image_<ID>.png` | **폴더 스캔 `floor_<N>/<ID>/*`** |
| 카메라 | 1대 (`camera.deviceId` 단일) | **최대 2대 동시, 세트별 독립** |
| 출력 | 단일 ScreenSpaceOverlay 캔버스 | **디스플레이(프로젝터)별 분리 출력** |
| 보정값 | 마커 ID당 1벌 | **세트 × 마커 ID당 1벌** |
| 부하 | 단일 화면 전제 | **한 PC에서 4화면 + 2카메라 + 영상 디코딩** |
| 키워드 월 | 없음 | 프로젝터 2대분 별도 화면 필요 |

재사용할 핵심은 `ArUcoHomography`(4꼭짓점 → 평면)와 `ArUcoWarpedImage`(비사각형 워프 UI)다.
이 둘은 그대로 쓰고, 그 위의 **검출기·이미지 라이브러리·오버레이는 세트 단위로 재구성**한다.

### 기타
- `Assets/AVProVideo/` — 영상 재생. Windows 플러그인 포함. (에셋스토어 유료)

- `Assets/StreamingAssets/Setting.json` — 현재 비어 있음(`{}`). **여기에 `floor`와 세트 정의를 넣는다.**

| 콘텐츠 위치 | `floor_<N>/<마커ID>[_제목]/` 폴더 안의 파일 | §4 |

| 배치 저장 | 세트 공통 → 마커 → 파일(`items[]`) 세 겹 | §6 |

| 재생 정책 | 보이는 동안 루프. 놓치면 멈춤, 20초 안에 돌아오면 이어서, 넘기면 되감기 | §5 |
| 관람 기록 | 1초 이상 유지 = 관람 1회. 건별 CSV 를 `persistentDataPath/stats/` 에 날짜별로 | §5 |
| 배치 편집 | 런타임 편집모드에서 조정 → 즉시 파일 저장. 세트별 분리 | §6 |
| 세트 정의 | `aruco.json`의 `sets[]`. 세트 수도 이 배열이 결정 | §6 |
| 키워드 월 | 낱말이 5가지 패턴으로 떠다님. 목록은 `floor_<N>/keywords.txt` | §3.1 |

### 미확정 (결정되면 이 절을 갱신)

1. **영상 규격** — 코덱/해상도. (H.264 / mp4 권장 — 하드웨어 디코딩)
2. **순위 화면** — 디스플레이 3·4(현재 키워드 월 프로젝터)에 "오늘의 추천", 오늘·일주일·한 달 순위 등을
   띄우는 안. 무엇을 어떤 기준으로 보여줄지, 키워드 월과 어떻게 나눌지 미정. 재료가 되는 관람 기록은
   건별로 남기고 있다(→ §5).
3. **동시 인식 마커 수 상한** — 책자를 여러 명이 동시에 올릴 때의 처리.
   ArUco PC 한 대가 세트 2개를 돌리므로 영상 동시 디코딩 상한과 직결된다.
4. **키워드 목록 내용** — 표시 방식과 구조는 정해졌다(→ ARCHITECTURE §10).
   실제 낱말은 아직 예시 상태이며, `floor_<N>/keywords.txt` 에 층별로 채우면 된다.
5. **디스플레이 번호 배정** — `aruco.json` 의 `sets[].displayIndex` 와 `keywordwall.json` 의 `walls[]` 로 지정하며,
   겹치면 시작할 때 경고한다. 역할을 나눈 뒤로는 ArUco PC 가 0·1번, 월 PC 가 0·1번으로 단순해졌지만
   Windows 가 매기는 번호와 물리 프로젝터의 대응은 현장에서 확인해 넣는다.
6. **월 연출에 통계를 어떻게 쓸지** — 월 PC 까지 관람 기록이 도착하는 경로는 만들어져 있다(→ §5).
   무엇을 보여줄지(오늘의 추천 · 순위 · 키워드 강조 …)가 정해지면 `ViewLog.ReadDay` / `Recorded` 위에 붙인다.

## 9. 개발 원칙

- 층·장비 수 차이는 **코드 분기가 아니라 설정 데이터**로 흡수한다. 빌드는 하나로 유지한다.
- 마커/콘텐츠 추가는 **파일만 넣으면 되는** 구조를 유지한다(코드·설정 수정 불필요).
- 검출·표시는 **세트 단위 인스턴스**로 만든다. 카메라/마커 상태를 전역 싱글턴에 두지 않는다.
- 현장 미세조정(위치·크기·회전)은 런타임에서 가능해야 하고, 그 값은 **세트별로** 파일에 영속화한다.
  에디터를 열어야만 고칠 수 있는 값은 만들지 않는다.
- 전시장 PC는 예고 없이 꺼진다. 상태는 **바뀐 시점에 저장**하고, 종료 처리에 의존하지 않는다.
