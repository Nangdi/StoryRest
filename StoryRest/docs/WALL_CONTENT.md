# 스토리쉼터 벽면 질문 · 해시태그 규약

전북 과학관 **스토리쉼터** 전시물 110개의 질문·해시태그를 벽면 스크린과 마커에 어떻게 대응시키는지 정한 문서.
StoryRest 뿐 아니라 같은 전시물을 다루는 다른 프로젝트도 **이 번호 규칙과 자료를 그대로 쓴다.**
다른 프로젝트로 옮겨 쓸 수 있도록 StoryRest 코드에 기대지 않게 적었다. 바뀌면 여기부터 고친다.

- 작성 2026-09-30 · 갱신 2026-10-01 (핵심/자세히 명칭, 연출안 PDF 반영)
- 미정 항목은 **[미정]** 으로 표시했다. 확정되면 표시를 지우고 날짜를 남긴다.

## 1. 원천 자료

| 자료 | 위치 | 내용 |
|---|---|---|
| 원고 정리본 | `바탕화면/스토리쉼터_벽면스크린_전시물제목_해시태그_띄어쓰기_260929_v02.md` | 전시물별 질문 제목 · 핵심/자세히 해시태그 (원고 표기는 쉬움/어려움, 띄어쓰기 적용) |
| 벽면 디자인 | `바탕화면/전북과_스토리쉼터-벽면(양산)_260929_RGB.psd` | 위 원고를 레이어로 조판한 것 + 벽면 분류 문구 |
| 원고 원본 | `[쉽게/어렵게 알아보기-1F/2F/3F] 스토리쉼터 연출 원고_2609xx.pptx` 6개 | 정리본의 출처 |

원고 정리본과 PSD 는 **질문 문장 · 태그 · 띄어쓰기까지 110개 전부 일치**함을 확인했다(2026-09-30).
둘이 어긋나면 PSD 를 화면 표기의 기준으로 본다 — 관람객이 보는 것은 PSD 조판이다.

### PSD 레이어 구조

```
1F / 2F / 3F
├─ N층 해시태그 키워드
│  └─ N-<번호>          그룹. 안에 태그 하나당 텍스트 레이어 하나 (핵심 ∪ 자세히 태그가 합쳐져 있음)
└─ N층 전시물 질문       텍스트 레이어 N-<번호>. 줄바꿈(\r) 포함
벽면 분류 문구           텍스트 레이어 9개
```

- 레이어 이름은 CP949 로 저장돼 있다. `psd-tools` 로 읽으면 `name.encode('latin-1').decode('cp949')` 로 되돌린다.
- 글꼴: 태그 Paperlogy 7Bold 40px · 질문 Paperlogy 8ExtraBold 82px(행간 93px, 가운데 정렬) · 분류 문구 Paperlogy 5Medium 50px.
- 캔버스는 1920×1080 이지만 **벽 출력은 1920×1200(16:10)** 이다. 가로가 같으므로 글자 크기는 그대로 쓰고, 배치 좌표만 세로를 다시 잡는다.

## 2. 전시물 ↔ 마커 번호

> **용어** — 한 전시물에는 **핵심**과 **자세히** 두 버전이 있다(2026-10-01 명칭 확정).
> 원고·원천 파일에는 각각 **쉬움**(`쉽게 알아보기`) · **어려움**(`어렵게 알아보기`)으로 적혀 있으니 같은 것으로 읽는다.

**전시물 n 번 → 마커 `2n-1`(핵심) · `2n`(자세히).** 홀수가 핵심, 짝수가 자세히다.

| 층 | 전시물 | 원고 번호 | 마커 |
|---|---:|---|---|
| 1F | 23 | 01–23 | 1–46 |
| 2F | 36 | 01–36 | 1–72 |
| 3F | 51 | 01–18, 20–52 | 1–36, 39–104 (**37·38 빈자리**) |

- n 은 **원고 번호** 그대로다. 3F-19 는 원고에 없지만 번호를 당기지 않는다 — 책자에 이미 인쇄된 마커와 어긋나기 때문이다.
- 마커 번호는 층마다 1번부터 다시 시작한다(층 = 별도 PC · 별도 콘텐츠 폴더).
- 예: 1F-01 → 1·2, 1F-02 → 3·4, 2F-05 → 9·10, 3F-20 → 39·40, 3F-52 → 103·104.

## 3. 질문

- **핵심과 자세히의 질문 문장은 같다**(110쌍 전부). 그래서 질문은 전시물 단위로 하나이고, 두 마커가 같은 질문을 가진다.
- 원고 표기를 고치지 않는다. 예: 3F-29 "어떻게 복제 될까?" 는 원문 그대로.

## 4. 해시태그

- 원고의 해시태그는 핵심/자세히 별로 따로 있고, 이미지도 마커 폴더별로 나눠 두었다(홀수 = 핵심, 짝수 = 자세히 태그).
- **벽에서는 둘을 합쳐 쓴다**(2026-10-01). 한 질문의 태그 = 핵심 ∪ 자세히 (같은 글자는 하나로). §5.
- 102개 전시물은 두 버전의 태그가 같다. 다른 것은 아래 7개뿐이다.

| 전시물 | 핵심 | 자세히 |
|---|---|---|
| 2F-05 굴렁쇠 | 마찰 · 회전판 · 상대 속도 | 굴림 운동 · 마찰력 · 상대 속도 |
| 3F-03 토네이도 | 상승 기류 · 기압 · 연직 바람 시어 | 상승 기류 · 기압 · 적란운 |
| 3F-04 태풍체험 | 바람의 세기 · 풍속 · 순간 풍속 | 기압 경도력 · 전향력 · 풍속 |
| 3F-06 지구의 자전효과 | 전향력 · 지구 자전 · 위도 | 전향력 · 지구 자전 · 좌표계 |
| 3F-08 내가 만드는 지진 | 지진파 · 지진계 · 지진 | 지진파 · 지진계 · 관성 |
| 3F-09 움직이는 땅 1 | 판 · 맨틀 · 판의 경계 | 판 구조론 · 맨틀 대류 · 판의 경계 |
| 3F-10 움직이는 땅 2 | 원시 지구 · 맨틀 상부 · 지구 내부 열 | 원시 지구 · 맨틀 대류 · 지구 내부 열 |

- **2F-33 자세히(2층 66번)는 원고에 태그가 없어 비워 둔다.** 핵심 태그로 채우지 않는다. 원고가 확정되면 넣는다.
- 화면에는 `#` 을 붙이지 않는다. 태그 글자만 띄운다.

## 5. 벽면 화면 구성

출처: `바탕화면/스토리쉼터 벽면 스크린 연출안.pdf` (p1 규칙, p2 화면 예시).

- 층마다 벽 스크린이 **두 개**(디스플레이 1 · 2)다(키워드 월 프로젝터 2대). 스크린끼리는 독립이다.
- 표시 방식은 **이미지 우선**이다(§6). 이미지로 안 되면 텍스트로 띄운다.
- **"선택" = 마커가 인식되어 관람으로 세어진 것**(관람 기록).
- **핵심 · 자세히 마커는 같은 질문으로 합쳐 센다**(2026-10-01). 순위 · 최소 선택 · 중복 판단 모두 전시물(질문) 단위다.
- 기간은 **최근 기준**이다(2026-10-01). 한 주 = 최근 7일, 한 달 = 최근 30일, 금주 = 최근 7일.

### 한 스크린의 구성 (2026-10-01 확정)

- **질문 2개**가 화면을 떠다닌다. 각 질문 **위에 분류 문구**가 붙어 함께 움직인다.
- 두 질문의 해시태그(각 질문의 핵심 ∪ 자세히)를 모아 그중 **랜덤 3~4개**가 질문보다 **작은 크기로** 같은 스크린 안을 함께 떠다닌다
  (다른 스크린으로 넘어가지 않는다).
- 크기 위계: 질문(굵고 큼) > 해시태그 > 분류 문구(작은 글씨, 질문에 붙음). p2 예시 참고.

### 분류 문구와 선정 기준

한 줄에 문구가 둘(`A / B`)인 경우는 **둘 중 랜덤**으로 골라 붙인다 — 같은 기준인데 문구만 바꿔 단조로움을 피한다.

| 구분 | 분류 문구 | 질문 선정 기준 | 스크린 |
|---|---|---|---|
| 조건 | 이번 주 호기심 1위 | 해당 층에서 최근 7일간 **가장 많이 선택된** 질문 | 왼쪽 벽(디스플레이 2)만 |
| 조건 | 이번 달 호기심 1위 | 해당 층에서 최근 30일간 **가장 많이 선택된** 질문 | 오른쪽 벽(디스플레이 1)만 |
| 조건 | 지금 누군가가 궁금해한 질문 | **방금 인식된** 질문 (아래 "즉시 교체") | **세트 A → 디스플레이 1(오른쪽 벽), 세트 B → 디스플레이 2(왼쪽 벽)** |
| 조건 | 아직 만나보지 못한 질문 / 이 질문의 첫 탐험가를 찾습니다 | 최근 7일 **선택 횟수가 가장 적은** 질문 중 랜덤 1개 | — |
| 랜덤 | 이 질문도 함께 만나보세요 / 쉬는 동안 궁금증 하나 / 잠깐, 그게 정말이야? / 어디 한번 알아볼까요? | 랜덤 선정. **두 스크린에 같은 질문이 동시에 나오지 않게** | — |

- 왼쪽 전시대 = **세트 A**, 오른쪽 전시대 = 세트 B. **디스플레이 1 = 오른쪽 벽, 디스플레이 2 = 왼쪽 벽**(2026-10-01).
  전시대에서 찍으면 마주 보는 벽에 뜬다(정면성). 1층은 세트 A 하나뿐이라 "지금 누군가" 는 디스플레이 1 에만 뜬다.
- p2 예시: 한 스크린에 "이번 주 호기심 1위 — 밤하늘을 수놓는 오로라는 어떻게 만들어질까?" 와
  "이 질문도 함께 만나보세요 — 생명이 살기 좋은 행성의 위치는?" 두 질문이 뜨고, 두 질문의 태그가 흩어져 있다.

### 교체 (2026-10-01 확정)

- **주기 교체** — 분류(와 질문)는 **2~3분마다** 자연스럽게(페이드 등) 바뀐다.
  **칸마다 시차를 둔다** — 한 스크린의 두 질문이 각자 타이머를 갖고 하나씩 바뀐다. 화면이 한꺼번에 비지 않는다.
- **즉시 교체 — "지금 누군가가 궁금해한 질문"**
  - 마커가 인식되면 그 질문을 **세트 A 면 디스플레이 1, 세트 B 면 디스플레이 2** 에 띄운다.
  - 그 스크린에 떠 있던 두 질문 중 **오래된 쪽과 자연스럽게 교체**한다.
  - 이 분류가 **층 전체(두 스크린 어디에도) 떠 있지 않을 때만** 뜬다. 한 번에 하나다.
    떠 있는 **30초 동안 다른 인식이 와도 이 분류를 갱신하지 않는다**(너무 자주 바뀌지 않게).
    마커 인식 자체를 무시하는 것은 아니다 — 투사 · 관람 기록은 평소대로 하고, 벽의 "지금 누군가" 만 다시 바꾸지 않는다.
  - **30초만 머물고** 물러난다. 다른 분류처럼 2~3분 주기를 따르지 않는다. 물러난 칸은 주기 교체로 새 분류를 뽑는다.

### 폐기

- 기존 StoryRest 벽의 **왼쪽 위 주제 카드**(오늘의 추천 · 오늘/이번주/이번달 베스트셀러, `PROJECT_SPEC.md` §3.1)는 **폐기**한다(2026-10-01).
  이 절의 구성이 대신한다.

### 세부 규칙 (2026-10-01 확정)

1. **"인식" = 관람으로 세어지는 순간**(마커 1초 유지, `viewMinDwellSeconds`). 스치듯 잡힌 오인식은 벽에 뜨지 않는다.
2. **주기 교체 때 분류 뽑기** — 그 스크린에 올 수 있는 분류 중 같은 확률로 랜덤.
   1위 분류는 정해진 벽에서만 뽑고, "지금 누군가" 는 주기 교체 후보가 아니다(인식으로만 뜬다).
   한 스크린의 두 칸이 같은 분류가 되지 않게 하고, 두 스크린에 같은 질문이 동시에 뜨지 않게 한다.
3. **겹칠 때 · 기록이 없을 때** — 이번 주 1위와 이번 달 1위가 같은 질문이면 나중에 뽑히는 쪽을 다른 분류로 바꾼다.
   기록이 없는 분류(개관 직후 1위 등)는 건너뛴다. "아직 만나보지 못한 질문" 은 기록이 없으면 전체가 0회라 전체 중 랜덤이 된다.

## 6. 이미지 규격 · 폴더

```
StreamingAssets/
├─ floor_<N>/<마커>/
│  ├─ sprite/NN_<태그>.png      해시태그. NN = 원고의 태그 순서
│  └─ question/question.png    질문. 핵심·자세히 두 마커 폴더에 같은 그림
└─ wall_titles/NN_<문구>.png    분류 문구 9개 (층 공통). 파일명에서 ? 는 뺐다
```

- **흰 글씨(#FFFFFF) + 투명 배경 PNG**, 글자에 맞춰 여백을 잘라낸다(4px). 색은 프로그램이 입힌다.
- 해시태그는 PSD 크기의 **3배**(글자 120px, 이미지 높이 약 113px)로 그린다. 벽에서 긴 변 360~760px 로 확대되므로 PSD 원본 크기(높이 35px)로는 흐려진다.
- 질문 · 분류 문구는 PSD 크기 그대로(질문 82px, 분류 50px).
- **PSD 래스터를 잘라 쓰지 않고, 레이어의 텍스트를 같은 글꼴로 다시 그린다.** 크기를 자유롭게 바꿀 수 있고 색이 섞이지 않는다.
- 글꼴 파일: `Assets/10.Font/Paperlogy-5Medium.ttf` · `Paperlogy-7Bold.ttf` · `Paperlogy-8ExtraBold.ttf`.

### 다시 내보내기

PSD 나 원고가 바뀌면 `Tools/wall_export/export_wall.py` 를 돌린다.

```
pip install -r Tools/wall_export/requirements.txt
python Tools/wall_export/export_wall.py <출력폴더> [PSD 경로] [원고 md 경로]
```

- 출력폴더를 임시 폴더로 주고 결과를 확인한 뒤 `StreamingAssets` 로 복사하는 것을 권한다.
- **`floor_<N>/` 안의 그림은 git 에 올라가지 않는다**(`.gitignore` — 콘텐츠는 폴더 구조만 관리). 새로 클론한 PC 나 전시장 PC 에서는
  이 스크립트로 다시 만들거나 파일을 직접 복사한다. 층 공통인 `wall_titles/` 는 커밋돼 있다.
- 스크립트는 원고 md 로 핵심/자세히 태그를 나누고, PSD 와 원고가 어긋나는 곳(문장·태그·띄어쓰기·누락)을 끝에 보고한다.
- `manifest.json`(마커별 전시물명 · 질문 · 태그 목록)도 함께 만든다.

## 7. 원근보정 (카메라 ↔ 프로젝터)

- **카메라는 적외선(IR 패스 필터)이다.** 프로젝터 빛은 가시광이라 카메라에 보이지 않는다.
  → 투사 마커를 자동으로 읽는 보정은 원리적으로 안 되고, **실물 마커를 놓는 수동 보정**만 쓴다.
- 프로젝터가 네 귀퉁이에 사각형을 쏘면(사람 눈용), 그 안에 실물 마커를 놓고(카메라용) 한 점씩 확정한다.
- **네 점 모두 같은 마커 한 장**을 옮겨 가며 써도 된다. ID 는 보지 않고 화면에서 가장 크게 잡힌 마커의 중심을 쓴다.
  그러므로 보정 중엔 카메라 시야에 마커를 **한 장만** 둔다.
- 사각형 크기를 실물 마커 크기에 맞춘다 — 대응점은 마커 중심이라, 크기가 다르면 그만큼 보정이 밀린다.
- 사각형 자리는 **책자가 놓이는 영역의 네 귀퉁이 가까이** 둔다. 네 점이 둘러싼 안쪽이 가장 정확하고 밖으로 갈수록 오차가 커진다.
- 인쇄한 마커가 IR 에서 검게 보여야 한다. 염료 잉크는 IR 을 통과시켜 하얗게 보일 수 있다(레이저·카본 잉크는 괜찮다).
- StoryRest 의 조작은 `ARCHITECTURE.md` §1 · §7 (F2 → F3 → Space 두 번 → 방향키로 자리 · +/- 로 크기 → Space 로 점 확정).

## 8. 빌드 환경 — 스마트 앱 컨트롤

Windows 11 **스마트 앱 컨트롤**이 켜져 있으면 Unity 빌드가 실패한다.

```
Internal build system error. BuildProgram exited with code 1.
System.IO.FileLoadException: Could not load file or assembly 'Bee.NativeProgramSupport' ... (0x800711C7)
```

- `0x800711C7` = 앱 제어 정책이 파일을 차단함. Unity 빌드 도구의 서명 없는 DLL 이 막힌 것이고 코드 문제가 아니다.
- 확인: 레지스트리 `HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy` 의 `VerifiedAndReputablePolicyState` 가 `1` 이면 켜짐(차단).
  이벤트 뷰어 `Microsoft-Windows-CodeIntegrity/Operational` 에 3033 · 3077 이 남는다.
- 해결: **Windows 보안 → 앱 및 브라우저 컨트롤 → 스마트 앱 컨트롤 → 끄기** 후 Unity 재시작. 파일별 예외는 없다.
  끄면 다시 켜기 어려울 수 있다(과거엔 Windows 재설치 필요).
- 전시장 PC 도 Windows 11 이면 서명 없는 빌드 결과물이 막힐 수 있으니 설치 때 같이 확인한다.
